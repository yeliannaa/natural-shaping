# 移植与首次使用

整个 `natural-shaping` 文件夹是一个独立 skill；保留目录结构后，放进目标应用支持的技能目录。不需要安装原作者的其他修图 skill。首次使用先确认目标应用已识别 `SKILL.md`，再检查实际要用的工具入口；选择 PS／随包脚本路线时用合成小图验证。Qwen、Photoshop 和本地 GPU 均不是整个 skill 的必备条件。

## 路径约定

- Markdown 链接相对于**链接所在文件**解析；`SKILL.md` 所在目录是技能根。脚本和文档均随包携带，不应依赖原作者机器的目录。
- 执行者根据本次读到的 `SKILL.md` 位置取得技能根，根据用户授权的工作目录取得任务根；必要时解析为本机绝对路径传入 Photoshop 或命令行。可移植意味着没有固定机器路径，并非取消运行时路径校验。
- 默认不向技能安装目录写照片、PSD、预览、日志、Python 环境或模型缓存；这些属于任务目录或用户选择的缓存目录。源图只读，产物使用新文件名。
- 示例中的 `SkillRoot`、`JobRoot`、输入文件及画布坐标均由当前任务提供。包含空格或中文的路径须通过结构化参数传递，PowerShell 使用 `-LiteralPath` / `Join-Path`；不得拼入未经转义的 shell 代码。

## 能力与依赖

| 路线 | 需要目标环境提供 |
|---|---|
| 看图诊断、构图与验收 | 本地文件读取及图像查看能力；生成的参考图不能替代真实证据 |
| 原生 PS 精修 | Photoshop 与可执行 ExtendScript 的连接；包内 runtime 使用 ES3/传统 JSX。RetouchRuntime 1.0.7 的可选原生液化模块当前限定验证环境为 Photoshop 21.2.9，其他版本先验证本轮入口 |
| 内置生成／编辑 | 当前应用可用且获授权的图像工具，由 Codex 调用原图进行编辑；无 Qwen 可独立执行此路线，具体型号未知时如实记录 |
| Qwen（可选后端） | 用户选用且当前已接入的本地或服务入口；另行提供程序、模型和资源，不随包安装、不作为内置路线的前提 |
| 混合精修（按需） | 当前可用的生成与局部编辑工具；可靠对齐后才合入，缺少 PS 不妨碍内置编辑，但不可承诺 PSD 或原生细节保留 |
| 会话内交互对照 | 当前应用的可视化能力；无此能力时生成等尺度、限高静态对照并保留原尺寸成片 |
| PNG 文件验收 | PowerShell 的 .NET 编译能力；[无损压缩脚本](../scripts/recompress_png.py)另需 Python 3.11+，无第三方依赖 |
| 自动主体蒙版（可选） | 独立 Python 环境、CPU 推理依赖及模型；见[蒙版工具](mask-tools.md)，不是使用整个 skill 的前提 |
| 身体定位参考（可选） | Python、MediaPipe 与显式提供的本地 pose 模型；[身体参考 helper](../scripts/build_body_reference.py)只辅助定位，缺依赖／模型继续人工，细节见[轮廓参考](shape-and-pose.md#可选身体参考只辅助定位) |
| 数值液化网格制作（按需） | [网格 helper](../scripts/build_liquify_mesh.py)仅需 Python 标准库；按人工确定的本图范围与数值制作内嵌 v4 `LqMe`，不自动识别或决定美型 |

skill 本身不会安装软件、授予工具访问权或搬运其他应用的连接。已选择生成路线后，无 Qwen／Qwen 不可调用且用户未限定后端时，由 Codex 选择当前可用内置生成／编辑继续；无 PS 时走可用生成或栅格路线，不反复要求安装可选工具。当前平台规则和用户指定后端优先，后端切换不扩大确认范围。所有编辑能力都不可用时如实说明，只完成分析；不要把计划、提示词或草图说成已经完成的精修。选择标准见 [后端选择](cos-retouch-engines.md#后端选择与缺少工具时的执行)。

## 调用参数约定

文档中的 PowerShell 示例均采用参数块：把代码存到**任务目录**中的 `.ps1` 后，传入本次技能根与任务根。`SkillRoot` 是含 `SKILL.md` 的现有文件夹；`JobRoot` 是已授权的现有任务文件夹。相对参数按调用时的工作目录解析。

Photoshop 示例是函数，执行器把当前解析后的路径和已打开文档的唯一名称作为参数传入。输出根必须与 `allowlistedOutputDirs` 精确匹配；原生液化读取外部任务网格时按 [runtime API](ps-runtime.md) 使用 `allowlistedInputDirs` 与解析后的绝对文件路径。这些列表不能代替宿主环境的实际读写权限，也不允许自动套用历史照片的网格。

原生液化默认 `mergedVisible` 禁用 `parent`、新层根级置顶，并要求根级可见、100% opacity／fillOpacity、Normal、无 user／vector mask 或 layer effects 的 Photoshop Background 确定 alpha 不透明；普通全画幅 layer bounds 不足以证明它。`target` 用复制层替换并隐藏 donor，仅允许 mask 缺省／`white`、opacity 缺省／100、visible 缺省／`true`，默认保持其原组／栈位置，比较时隐藏新层并恢复 donor 原可见状态。源层快照会包含当前可见的前序形变，manifest 记录依赖状态而不自动验证来源 hash；调用者按实际源版本绑定。`mergedVisible` 的 ROI 羽化不构成严格支持边界，具体选路与检查见 [生产参考](production-retouch.md#native-geometry-and-optional-body-reference)。

身体 helper 用 `--model-path` 明确指定已准备的本地模型，不联网下载，不随包提供虚拟环境、模型权重或固定缓存路径。关键点／置信度需人工对原图复核；坐姿和遮挡可能产生高置信误判，不能直接转为身体轮廓或保护区。模型缺失是这一可选参考不可用，不是整个 skill 或人工精修不可用。

## 首次验证

只验证本轮使用的路线，不为缺少未使用工具而阻断任务。内置路线先确认图像输入／编辑接口真实可用，随后按已确认范围检查实际候选，不额外要求 PS 合成文档或一次无关付费生图。PS／随包脚本路线首次在新环境或代码更换后，用新建合成文档验证要用的曲线、蒙版、预览、原生导出或液化入口，确认原文档未被覆盖、产物尺寸／位深／颜色定义正确。已确认的环境与代码可缓存探测结果，每张实际照片仍核本次效应与范围，不重跑整套合成测试。

原生液化只声明已验证的 `liquifyFace.faceWidth` 与 `liquifyMesh` 内嵌 v4 `LqMe`，不接受 `LqMD`／v3，不证明全部五官参数、多人物／批量或其他 PS 版本兼容。具体运行与生产验证状态见 [原生液化证据](../assets/evidence/native-liquify-validation.json)；身体 helper 的检测与人工复核见 [身体参考证据](../assets/evidence/body-reference-validation.json)。零参数不变、重放一致与命令成功均不证明照片审美通过，仍按 [三道门槛](quality-review.md#三道采用与交付门槛) 复查实际结果。

其他后端按实际入口核资源及输出。一次成功不证明全部功能、版本兼容或照片达标；PS 超时先读 manifest 与实际图层，生成超时先查任务和产物状态，再决定续跑。回滚是否成功以实际状态和 `rollback`／`cleanupErrors` 记录为准；失败时保留日志并停止当前不确定状态的后续修改，不写成已撤回。

## 包内资料与校验

案例图、已核读教程帧及笔记按问题读取；不是每次使用都打开全部资料或访问全部外链。外链保留来源，本地已携带的证据无需再次下载。历史记录中的 `origin-not-bundled:` 或 `origin:unbundled/` 只是未携带来源标识，不是运行依赖、可点击资源或重放脚本。JSON 的路径基准见各记录的移植说明；主索引使用 skill 根，其余证据通常相对于记录所在目录。历史 SHA256／bytes 属于原始证据，改写后的当前字节以包根 `package-manifest.json` 为准。`assets/evidence` 内的旧记录只作证据阅读，不重放其中的历史命令或照片坐标；执行按主 skill 与随包脚本的现行文档。

在任意工作目录运行 `python <技能目录>/scripts/validate_portable.py` 可校验文件清单、SHA256及显式本地引用；脚本从自身位置定位技能根，不联网、不修图、不写包内文件。检测不代替图像验收或执行环境测试。

随包保留原使用者的少量照片局部与最终 JPG 作为风格/失败证据，不含完整拍摄库、PSD、API密钥、会话配置、虚拟环境或模型权重；第三方教程片段保留原作者及来源归属，不附整个视频或第三方付费插件。
