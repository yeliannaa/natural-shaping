# Cos 精修执行方法与引擎参考

执行前置遵循 [主 skill](../SKILL.md)：新图及完整重修先拆解构图、展示源图草图并等待用户确认；试修、生成候选和合成属于确认后的生产操作，不能冒充“草图”绕过确认。已确认方案内的局部返修沿用原确认。历史照片中的具体授权不传给新任务。

外部资料核读于 2026-10-05，原机实验整理至 2026-10-09。这是选路参考，不是朋友设备的能力清单：外部候选未因写入本包而安装、授权或接入；原机已验证的接口也须在当前环境确认实际可调用。接口存在、操作执行、成片检查和用户认可分别记录。

## 把目标落实到实际编辑

单张任务用简短记录连接：原片／稳定母版 → 本图肤质、五官、身形目标 → 保护关系和范围 → 实际方法 → 返回结果 → 检查。批量任务再保留每张输入与输出对应关系，不按返回顺序猜配。

构图、遮挡和主光先确定，再落实人物与协调的背景／光色。工具沿当前请求与平台规则选取；调用内置图像工具时读当前工具说明及可访问的 imagegen 技能，调用其他已接入后端时读该后端说明；不要求使用者另装原作者的个人 skill。实际看原图并作为编辑输入。PS 路线把目标落到修复、纹理、曲线、颜色和几何责任层。提示词、图层名称和任务清单都不算已完成效果。

| 目标 | 本图需要明确的内容 |
|---|---|
| 肤质 | 细腻与平整程度，脸身如何统一，保留哪些妆面与结构阴影 |
| 脸型／五官 | 具体比例或轮廓及收益，保护身份、视线和表情；不同时要求五官完全不动和明显几何精修 |
| 身形 | 适用的肩颈、手臂、腰髋或腿部改善，保护关节、硬衣装和支撑／握持 |
| 角色细节 | 实际眼线、美瞳、面纹、假发、饰件、专有花纹及道具锚点 |

局部返修从稳定节点分支。蒙版实际限制范围；提示“选区外不变”不保证像素不变。几何域应覆盖关联部位及平滑过渡，过紧蒙版会截断脸颈或衣装。像素差分验证范围，同尺度目视判断收益、本人感与妆造。

## Codex 主导与可选生成后端

有效构图确认之后，由 Codex 把肤质、五官、身形、角色感及光线背景连接成整体目标，选择工具、约束范围、查看真实产物并决定是否采用。用户确认审美方向和最终认可；候选可用性与用户接受分别记录。美型细分见 [人像美颜](portrait-beauty.md#美型的判断与执行分工)。

| 职责 | 实际工作与边界 |
|---|---|
| Codex 主导 | 判断轮廓、妆面、光影、姿态和透视各自的问题；联看整脸与颈肩、胸腰髋与腿脚，提出方法并检查可见收益，不只修用户最后指出的一处 |
| 生成后端 | 按确认范围提供补光、背景、美型、复杂修复或补全候选；Qwen 与内置图像工具均适用，提示词限制不等于真实蒙版或像素锁定 |
| PS／可用的局部编辑工具 | 原图上的精确光色、纹理、可控几何和局部融合；实际支持什么就执行什么，不把随包 runtime 当自动液化／身体识别 |
| 验收与认可 | Codex 检查目标完成度、身份妆造、整体比例、连接和细节；用户明确认可后才记终稿，不能以文件输出或第二检查者同意替代 |

### 后端选择与缺少工具时的执行

- 当前平台工具规则和用户指定路线优先。Qwen 已接入、可调用且资源允许时，可按本图收益选用；本包不含其可执行程序、权重或默认本机路径。
- **没有 Qwen 且用户未限定后端时，Codex 直接使用当前可用且获授权的内置图像生成／编辑工具。** 不把安装 Qwen、GPU 或本地模型列为使用前提，也不要求为等价后端重新确认同一范围。实际型号不可见时记录未知，不能按产品称呼猜型号。用户明确只用某个后端而它不可用时，说明缺口并确认可接受的替代，不擅自切换。
- 没有 PS 时，使用可用内置编辑或其他已授权的栅格工具完成适用工作；如实交付实际格式、尺寸及限制，不承诺 PSD、原像素保留或高分辨率恢复。无任何实际编辑工具时只完成分析和方案，并说明缺口。
- 本地生成资源不足时先回退可用后端或缩小到有完整上下文的局部测试。不能自行关闭未保存文档、改系统配置或购买云服务；单机的游戏暂停入口、显存和缓存路径不成为共享包要求。
- 同一问题从一次针对性候选开始，检查后再决定采用或换法，不默认串行测试所有模型。失败按主 skill 的停止条件处理；平台拒绝时遵守工具规则，不把裁剪或打码作为规避限制的方法。

### 候选如何采用

| 判定 | 采用条件与做法 |
|---|---|
| 整图采用 | 已确认范围支持整图处理，所有适用收益与保护项通过；明确生成尺寸与推断内容，不宣称原片高分辨率细节未变 |
| 局部融合 | 目标区域有收益，几何与连接可可靠对齐，接受范围外保留稳定源；用实际蒙版／合成控制覆盖，匹配光色、纹理尺度、噪点和接缝 |
| 仅作参考 | 光影或美型方向有价值，但妆造、结构或细节偏移使直接采用不合适；在原图上重做可执行调整，并检查实际结果，不把未经实现的光色迁移列为已有能力 |
| 退回稳定版 | 目标未达成、身份或结构受损、无法可靠对齐，或收益不足以抵偿融合与返修；保留失败记录，不掩盖未完成 |

只保留合格的局部改善；不能因为一个区域更自然而接受整图无关重绘。按 [验收与返修](quality-review.md#生成候选的采用检查) 检查实际输入、候选及最终合成；升采样不等于找回原细节。

## 原机已验证的 PS 几何路线

案例原机 Photoshop **21.2.9** 曾标定并执行：

```javascript
ArtLayer.applyDisplace(
  horizontalScale,
  verticalScale,
  DisplacementMapType.STRETCHTOFIT,
  UndefinedAreas.REPEATEDGEPIXELS,
  mapFile
)
```

这是按图定义数值场的位移滤镜，不是人体识别、语义塑形或脸部液化接口。首次迁移环境时先确认实际脚本入口与滤镜，并用可撤回小样验证方向和数值关系；包内历史标定不能证明当前设备已可执行。

- **层与数值图**：独立全画幅 RGB 像素层，激活目标文档／RGB 通道并取消选区。地图与画布同尺寸，保存为扁平 RGB8 PSD；数值图不能做 ICC 颜色转换，照片母版保持自身位深／配置。完成位移后用蒙版呈现完整影响域及平滑过渡。
- **标定关系**：`sourceOffset=(channel-128)*scale/100`，内容可见运动方向相反；R 横向、G 纵向、128 中性。原机 R=192、scale=16 时预期采样偏移 +10.24 px，实测内容向左约 **10.235 px**；scale=40 时 10 px 运动对应 25 级通道差值。滤镜刻度不等于位移像素或瘦脸百分比。见 [原机标定记录](../assets/evidence/ps-displace-calibration.json)。
- **视觉约束**：dora 第二轮把贴脸主发束误作皮肤边界，即使地图正 Jacobian、保护点中性，仍把发束带弯。需重定边界并恢复残留受损发丝；见 [v2 实际记录](../assets/evidence/dora-v2-edit-record.json)。该阶段无单独认可，后来的 v4 认可不回溯覆盖它。
- **依赖约束**：地图绑定源图、尺寸、裁剪及此前几何状态。替换上游形变后，检查合并像素层、补片、蒙版、背景虚化和光色快照是否已烘焙旧结果；必要时从可靠节点重建。隐藏旧源层不一定撤销下游形变，旧图坐标与幅度不作新图预设。

## 外部候选的证据边界

下表保留当时核读结果，未在本次打包中联网更新，也未用这些候选在案例原片上完成实测。

| 项目与来源 | 可借鉴部分 | 尚未实现或不能据此宣称 |
|---|---|---|
| [photo-cull-retouch 工作流](https://github.com/dudachun/photo-cull-retouch/blob/main/COSKIT_IMAGEGEN_WORKFLOW.md)与[主程序](https://github.com/dudachun/photo-cull-retouch/blob/main/scripts/photo_cull_retouch.py) | 选片／任务生成与真正修图分开，每张对应输入、输出和路线 | 默认依赖会话 imagegen，自身无完整五官／身体引擎；轻修提示词与身体缺项不能满足完整自然美型 |
| [CosKit](https://github.com/DongSky/CosKit) | 历史分支与蒙版外还原思路 | README 功能和 GPU 工程测试不证明 Cos 精修达标；本包未接入其合成实现或后端 |
| [GPUPixel 接口](https://gpupixel.pixpark.net/zh/call/beauty_effects)与[Windows 构建](https://gpupixel.pixpark.net/zh/guide/build) | 磨皮、美白及关键点驱动的瘦脸／大眼候选 | 仍需构建与接入；所核接口无腰腿塑形，基础美颜不等于完整五官精修 |
| [PixelFree C API](https://github.com/uu-code007/PixelFreeEffects/blob/master/doc/api_c.md)与[Python 示例](https://github.com/uu-code007/PixelFreeEffects/blob/master/SMBeautyEngine_win_python/main.py) | 文档覆盖皮肤、细分五官与身体参数 | 需匹配 DLL、模型和授权文件；所读 Python 示例无身体接口绑定，参数不等于实际比例变化百分比 |
| [skin-retouching-onnxruntime 主链](https://github.com/aoguai/skin-retouching-onnxruntime/blob/master/onnx_skin_retouching/runtime.py)与[部署记录](https://github.com/aoguai/skin-retouching-onnxruntime/blob/master/docs/ONNX_DEPLOYMENT_REPORT.md) | 脸部平整、可选局部祛瑕与提亮候选 | 需权重及环境；检测不到脸可能原图返回，无脸型或身体几何能力 |

photo-cull-retouch 的本地 baseline 主要是白平衡、对比度、肤色阈值／平滑和锐化。彩妆、彩光或非人类肤色需核查阈值；这是从实现得出的适用性判断，不是效果实测。选片分数不代表角色还原度，弱滤镜也不自动成为“高级精修”。

仅在任务确需新引擎时再核当前版本、许可、模型与平台。历史核读中 GPUPixel 标 Apache-2.0，PixelFree 仓库有 MIT 文件但运行 SDK 另依赖授权，ONNX 代码和模型许可须分别核实；这些记录不代替当前许可检查，也不表示运行资源已取得。本包不复制第三方实现。

接入后在可回退样片上分别验证皮肤、五官、身体模块：是否真实改变对应像素，是否保住妆面、美瞳、假发与硬衣装，整体及原尺寸是否改善。检测失败、无效参数或回退弱滤镜如实记录；先执行并看结果，再记能力可用，不预先承诺与像素蛋糕等效。

## 按问题选路

| 问题 | 优先考虑 | 需要检查的边界 |
|---|---|---|
| 现有肤质、光色与轮廓 | 可执行的修复、曲线、颜色和可控几何；效果不足时按收益测试限定范围的生成候选 | 保持本人感与妆造，同时判断精致度是否充分；无几何工具不等于无需美型 |
| 复杂补光与背景 | 生成参考候选或受控编辑，再决定直接采用、原图光色调整或局部融合 | 光线改善仍需单独核眼妆、美瞳、唇色、发饰和材质；不能把补光算作已完成五官／身形 |
| 假发／软布局部缺失或难修纹理 | 足够上下文的真实裁片约束生成，仅合入合格范围 | 供体可能移动结构，不能称原始细节恢复；对齐、材质和接缝均需看 |
| 衣带、鞋、球拍、专有武器 | 真实参考、连接与透视先行，有限试修后再细磨 | 可用材质不等于完整几何，自洽也不证明隐藏真结构 |
| 扩边或自主构图 | 按已确认取景有限试验，实际检查新增范围与动作是否达成 | 灰条仍在、花缘仍截断或人物并未重新布局都不算目标完成；新取景另确认 |

皮肤、假发、绒毛、蕾丝和丝袜按材质换方法。供体采纳范围外的脸、妆和饰件变化退回真实像素；原生方法足够时不固定先生成。

最新认可及保存状态见 [个人案例 NS08／NS09](personal-cases.md)；早期重绘、空场、大扩图、猜测枪尖均不追认为成功。只在需要复盘时读 [实验摘要](engine-experiment-history.md)，其中工具耗时不代表全流程速度。

## 三次原片实验的选路依据

原机 Qwen-Image-2.1 ncnn BF16、可执行版本 20261004 的实验提供以下边界；不是共享包默认模型、参数或速度保证，也不证明内置图像后端会有同样结果。历史成片示例的认可状态保持各自记录，不用新候选覆盖。

| 实验与原生候选尺寸 | 实际观察 | 用于后续判断 |
|---|---|---|
| 群像原片补光，896×896，469.02 秒 | 左侧脸与眼部补光明显，但眼妆、唇部等有重描；用户认可打光收益并指出妆造受影响 | 可测试光影候选，独立核妆造；原图光色重做是可选方案，尚非已验证的自动迁移能力 |
| 蕾姆原片去两处遮挡，768×1024，493.47 秒 | 两处遮挡去掉，新肩袖与拿相机的手连接较可信；仍有窄填边，隐藏部分为推断 | 复杂补全可尽早试；候选未因此获得终稿认可，合入前还需局部及画边检查 |
| 昔涟整理并左补花缘，768×960，453.24 秒 | 补光收益较小，左侧仍有约 39px 灰条，花缘仍截断，补全目标失败 | 保留实验失败与原稳定版；不裁掉灰条后宣称完成，不外推成所有扩图都不可用 |

这些耗时仅为本机单次生成，不包含拆解、融合、复核和保存；生成后尺寸也不能证明原片高分辨率细节保真。

## 速度、文件与恢复

复用建层、曲线、蒙版、位移编码与预览机制，按新图重定区域和强度。原蕾姆母稿约 1.61 GB、140 个含组层记录，减少重复合并、复制和全尺寸导出有实际价值；阶段用轻量全图与原尺寸局部，稳定后统一导出。全画幅位移图仍遵守真实接口限制，导出发现问题仍需返修。

历史备注：2026-10-07 的 previewBatch 候选像素／清理检查通过，但两组逐张／批量中位耗时 1222／1284 ms、1274／1409 ms 未证明加速，**未安装，也不是随包能力**。

连接超时后 PS 脚本可能继续执行，先查阶段标记、目标层和产物；共享 PS 写操作串行，独立只读诊断和固定候选复看可并行。生产细则见 [共用生产参考](production-retouch.md)。

历史生成服务未暴露具体型号，无相同输入、范围和验收标准的全流程速度对照，不称 GPT Image 2.5 或宣称提速倍数。PNGSaveOptions 曾在已转 sRGB 的文档导出时缺 ICC；需要补配置时只写入与像素相符的 ICC，并验证像素未变，指定配置不等于颜色转换。会话内对照按当前主 skill 和平台能力实现，旧尺寸不作默认值。
