# Cos 精修执行方法与引擎参考

执行前置遵循 [主 skill](../SKILL.md)：新图及完整重修先拆解构图、展示源图草图并等待用户确认；试修、生成候选和合成属于确认后的生产操作，不能冒充“草图”绕过确认。已确认方案内的局部返修沿用原确认。历史照片中的具体授权不传给新任务。

外部资料核读于 2026-10-05，原机实验整理至 2026-10-10。这是选路参考，不是朋友设备的能力清单：外部候选未因写入本包而安装、授权或接入；原机已验证的接口也须在当前环境确认实际可调用。接口存在、操作执行、成片检查和用户认可分别记录。

## 把目标落实到实际编辑

单张任务用简短记录连接：原片／稳定母版 → 本图肤质、五官、身形目标 → 保护关系和范围 → 实际方法 → 返回结果 → 检查。批量任务再保留每张输入与输出对应关系，不按返回顺序猜配。

构图、遮挡和主光先确定，再落实人物与协调的背景／光色。工具沿当前请求与平台规则选取；调用内置图像工具时读当前工具说明及可访问的 imagegen 技能，调用其他已接入后端时读该后端说明；不要求使用者另装原作者的个人 skill。实际看原图并作为编辑输入。PS 路线把目标落到修复、纹理、曲线、颜色和几何责任层。提示词、图层名称和任务清单都不算已完成效果。

| 目标 | 本图需要明确的内容 |
|---|---|
| 肤质 | 细腻与平整程度，脸身如何统一，保留哪些妆面与结构阴影 |
| 脸型／五官 | 具体比例或轮廓及收益，保护身份、视线和表情；不同时要求五官完全不动和明显几何精修 |
| 身形 | 适用的肩颈、手臂、腰髋或腿部改善，保护关节、硬衣装和支撑／握持 |
| 角色细节 | 实际眼线、美瞳、面纹、假发、饰件、专有花纹及道具锚点 |

局部返修从稳定节点分支。蒙版实际限制范围；提示“选区外不变”不保证像素不变。几何域应覆盖关联部位及平滑过渡，过紧蒙版会截断脸颈或衣装。像素差分验证范围，同尺度目视判断收益、本人感与妆造。

## Codex 主导与可选生成后端

有效构图确认之后，由 Codex 把肤质、五官、身形、角色感及光线背景连接成整体目标，选择工具、约束范围、查看真实产物并决定是否采用。用户确认审美方向和最终认可；候选可用性与用户接受分别记录。美型细分见 [人像美颜](portrait-beauty.md#美型的判断与执行分工)。

| 职责 | 实际工作与边界 |
|---|---|
| Codex 主导 | 从原片、角色妆造和当前要求定本图审美目标；判断轮廓、妆面、光影、姿态和透视，联看整脸与颈肩、胸腰髋与腿脚，提出方法并检查净收益，不只修用户最后指出的一处 |
| 生成后端 | 按确认范围提供补光、背景、美型、复杂修复或补全候选；Qwen 与内置图像工具均适用，提示词限制不等于真实蒙版或像素锁定 |
| PS／可用的局部编辑工具 | 原图上的精确光色、纹理、已验证的有限原生液化／位移和局部融合；身体识别另作可选定位参考，不自动决定轮廓或美型 |
| 验收与认可 | Codex 分别检查本图审美收益与身份、妆造、比例、连接和细节的可靠性；用户明确认可后才记终稿，不能以文件输出或第二检查者同意替代 |

### 后端选择与缺少工具时的执行

- 当前平台工具规则和用户指定路线优先。Qwen 已接入、可调用且资源允许时，可按本图收益选用；本包不含其可执行程序、权重或默认本机路径。
- 同一已确认方案中，现有真实像素可支持的小幅几何优先由可撤回的原生操作处理；复杂补全、隐藏结构或原生方法无法完成的局部问题再按收益使用既有生成／混合路线。工具选择不新增同一范围的审美审批。
- **本轮已选择生成路线、没有 Qwen 且用户未限定后端时，Codex 直接使用当前可用且获授权的内置图像生成／编辑工具。** 不把安装 Qwen、GPU 或本地模型列为使用前提，也不要求为等价后端重新确认同一范围。实际型号不可见时记录未知，不能按产品称呼猜型号。用户明确只用某个后端而它不可用时，说明缺口并确认可接受的替代，不擅自切换。
- 没有 PS 时，使用可用内置编辑或其他已授权的栅格工具完成适用工作；如实交付实际格式、尺寸及限制，不承诺 PSD、原像素保留或高分辨率恢复。无任何实际编辑工具时只完成分析和方案，并说明缺口。
- 本地生成资源不足时先回退可用后端或缩小到有完整上下文的局部测试。不能自行关闭未保存文档、改系统配置或购买云服务；单机的游戏暂停入口、显存和缓存路径不成为共享包要求。
- 工具故障、质量不合格和平台拒绝分别记录；平台拒绝时遵守工具规则，不把裁剪或打码作为规避限制的方法。候选重试按下方任务卡及主 skill 的停止条件处理。

### 一次候选的任务卡与提示

确认后先选本次最有价值、能独立验收的任务；常规瑕疵、精确光色与可控几何由现有编辑完成，困难补光、缺失结构或难修材质再按需生成。需要整图光线／比例上下文时用整图；问题集中且有完整连接上下文时可用裁片。不是每张都生成，也不默认全套目标一次交给模型。

使用现有调整记录，不另建审批表。送图前明确：**本次必须达成的结果、可采用区域、需保留的关键关系、原生源与输入尺寸、验收视图**。任务拆分不能删除已确认总目标；余下美型、背景或光线继续由对应工具完成。

提示组织为少量清楚的优先级，而非长串相互冲突的要求；可按本图改写这个骨架：

```text
编辑所附真实照片／裁片，维持原视角与动作。
本轮目标：[具体改变与位置；多个目标先列必要结果]。
保留：[对本图重要的主体、妆造、场景物件及连接锚点]。
结构要求：[握点到道具、腕到袖口、衣带到衣缘等完整关系]。
其余内容以源图为准；不额外改变未授权的脸型、表情或衣装设计。
```

按照片尺度说明位置，必要时附源图标注；原图／参考／标注图用途分别说明。美型任务可改变已授权的轮廓，不同时要求五官坐标完全固定。补光任务先说明原光源与各成员不同的补光需要，不把所有阴影抹平。提示词不是硬蒙版：必须实际看返回图的保护关系和遗漏，不能以“已写保留”判通过。

一次针对性候选后选整图、局部、参考或回退；只有明确可纠正的问题才改输入／提示再试，沿主 skill 的两轮停止条件执行，不默认遍历种子、分辨率和所有后端。减少返修是否节省总时间需实测；这轮证据不证明某种语言、提示长度或句式普遍更优。

### 局部输入与原生映射

区分**输入上下文**和**实际采纳范围**。输入应包含完整握持、腕袖、带缘或道具连接，并保留判断光线、透视及相邻材质所需内容；采纳区域可以更小。过紧裁片会缺依据，扩大裁片也不自动提高质量。脸不在输入只能记未观察，不称身份保真通过。

需合入原生图时记录源版本／尺寸、裁片 `[L,T,R,B]`、内容缩放尺寸、填边、返回有效区和实际蒙版。用真实裁片映射放回，不能以透明边界或图层包围框猜位置。边界坐标可写为 `x=L+(u-padX)*(R-L)/contentWidth`、`y=T+(v-padY)*(B-T)/contentHeight`；像素中心、取整及额外配准按实际实现核对。输出尺寸／画幅若变，重新确认映射，先比对至少两处分散的可见锚点，再融合。

模型原尺寸用于查新增重描；原生图用于查最终细节和接缝，两者都要看。统一真实色彩解释；带 alpha 的供体按用途核验，切勿无意以黑／白底污染半透明边缘，也不把透明素材一律转为不透明。未经确认的 ICC 不能靠随意贴标签当颜色转换；升采样只增加像素数。

### 候选如何采用

| 判定 | 采用条件与做法 |
|---|---|
| 整图采用 | 已确认范围支持整图处理，候选的目标／审美与可靠性分别通过，并另验实际交付文件；人物与构图／背景按本轮目标分别判断，不能用一项收益抵消另一项退步。明确生成尺寸与推断内容，不宣称原片高分辨率细节未变 |
| 局部融合 | 逐项选取有净收益的区域，几何与连接可可靠对齐，失败变化及接受范围外保留稳定源；用实际蒙版／合成控制覆盖，匹配光色、纹理尺度、噪点和接缝，合入后重看整体协调 |
| 仅作参考 | 光影或美型方向有价值，但妆造、结构或细节偏移使直接采用不合适；在原图上重做可执行调整，并检查实际结果，不把未经实现的光色迁移列为已有能力 |
| 退回稳定版 | 目标未达成、身份或结构受损、无法可靠对齐，或收益不足以抵偿融合与返修；保留失败记录，不掩盖未完成 |

只保留有净收益且能可靠采用的变化；按 [三道门槛](quality-review.md#三道采用与交付门槛) 分别检查实际输入、raw 候选和真实合成导出。候选被判局部可用后，合成仍可能因映射、遮挡暗边或板缝错接失败，不能继承 raw 通过状态。

## 原机已验证的 PS 几何路线

### 随包原生液化的有限能力

原机在 Photoshop **21.2.9** 已验证有限的原生液化入口。RetouchRuntime **1.0.7** 配合 [ps_liquify_runtime.jsx](../scripts/ps_liquify_runtime.jsx) 封装为两个操作，先加载液化模块再加载主 runtime；调用、源层／蒙版和输入路径要求集中见 [PS runtime API](ps-runtime.md)。具体合成探测、生产封装与实际输出的验证范围见 [原生液化证据](../assets/evidence/native-liquify-validation.json)，不能把一次命令成功扩大成所有液化功能兼容。

| 操作 | 当前支持 | 不能据此宣称 |
|---|---|---|
| `liquifyFace` | 已验证的 `faceWidth`，按本图本人感、轮廓与颈肩关系选幅；未支持参数应报错 | 眼、鼻、嘴等全部五官参数，多脸控制，滑杆数值等于瘦脸百分比 |
| `liquifyMesh` | 经校验的内嵌 v4 `LqMe` 网格；当前画布与网格尺寸限制按 API | `LqMD`、v3、任意 Photoshop 版本／批量兼容，自动人体识别或隐藏结构恢复 |

滤镜在独立副本上执行；`mergedVisible` 可用实际蒙版控制采纳范围，ROI 羽化只软化边缘，不保证矩形外无变化。自定义网格可用 [build_liquify_mesh.py](../scripts/build_liquify_mesh.py) 制作；其数值场由人工依据本图完整轮廓、连接、保护区与过渡域制定。网格合法、Jacobian 无折叠或保护点中性不能代替真实发束、关节、衣装和背景线判断；不能重放旧图网格或统一给所有人一个百分比。

源层方式分别处理：默认 `mergedVisible` 禁用 `parent`，需根级可见、opacity／fillOpacity 为 100%、Normal 且无蒙版／效果的 Photoshop Background 确定 alpha 不透明，新快照根级置顶。`target` 复制后隐藏 donor 作为替换层，仅允许 mask 缺省／`white`、opacity 缺省／100、visible 缺省／`true`，未指定 parent 时保持原组／栈位置；修前比较须隐藏新层并恢复 donor 原可见状态。可见的多次快照会烘焙前序形变，隐藏旧液化层并不消除新快照里的旧结果。manifest 的依赖层状态不能替代来源 hash，像素来源绑定由调用者完成；细节见 [生产参考](production-retouch.md#native-geometry-and-optional-body-reference)。

环境首次使用或代码更换时，用合成小图验证本轮要用的能力，包括零值的实际像素行为，并缓存结果，不逐图重跑整套技术探测。每张实际照片都要确认非零操作确有预期位移、保护区可靠、完整连接与纹理仍成立，并分别通过 [三道门槛](quality-review.md#三道采用与交付门槛)。实际测得的零参数不变、重放一致和 manifest 的完成状态只表明对应技术行为；像素效果未核与审美未过仍是待核／待修。

### 可选身体参考与人工轮廓

MediaPipe 可通过 [身体参考 helper](../scripts/build_body_reference.py) 辅助定位；显式提供本地模型，不联网下载，缺模型或识别失败直接继续人工。坐姿、遮挡与肢体交叠可能高置信误判；先对原图复核可见／推断关节、衣装边界和接触关系，再制定轮廓、锚点与保护区，不把关键点／分割输出直接当液化场或可靠身体测量。详细按需读 [轮廓参考](shape-and-pose.md#可选身体参考只辅助定位)，实测与人工复核分别见 [身体参考证据](../assets/evidence/body-reference-validation.json)；不额外增加用户审批。

### 数值位移滤镜

案例原机 Photoshop **21.2.9** 曾标定并执行：

```javascript
ArtLayer.applyDisplace(
  horizontalScale,
  verticalScale,
  DisplacementMapType.STRETCHTOFIT,
  UndefinedAreas.REPEATEDGEPIXELS,
  mapFile
)
```

这是按图定义数值场的位移滤镜，不是人体识别、语义塑形或脸部液化接口。首次迁移环境时先确认实际脚本入口与滤镜，并用可撤回小样验证方向和数值关系；包内历史标定不能证明当前设备已可执行。

- **层与数值图**：独立全画幅 RGB 像素层，激活目标文档／RGB 通道并取消选区。地图与画布同尺寸，保存为扁平 RGB8 PSD；数值图不能做 ICC 颜色转换，照片母版保持自身位深／配置。完成位移后用蒙版呈现完整影响域及平滑过渡。
- **标定关系**：`sourceOffset=(channel-128)*scale/100`，内容可见运动方向相反；R 横向、G 纵向、128 中性。原机 R=192、scale=16 时预期采样偏移 +10.24 px，实测内容向左约 **10.235 px**；scale=40 时 10 px 运动对应 25 级通道差值。滤镜刻度不等于位移像素或瘦脸百分比。见 [原机标定记录](../assets/evidence/ps-displace-calibration.json)。
- **视觉约束**：dora 第二轮把贴脸主发束误作皮肤边界，即使地图正 Jacobian、保护点中性，仍把发束带弯。需重定边界并恢复残留受损发丝；见 [v2 实际记录](../assets/evidence/dora-v2-edit-record.json)。该阶段无单独认可，后来的 v4 认可不回溯覆盖它。
- **依赖约束**：地图绑定源图、尺寸、裁剪及此前几何状态。替换上游形变后，检查合并像素层、补片、蒙版、背景虚化和光色快照是否已烘焙旧结果；必要时从可靠节点重建。隐藏旧源层不一定撤销下游形变，旧图坐标与幅度不作新图预设。

| [skin-retouching-onnxruntime 主链](https://github.com/aoguai/skin-retouching-onnxruntime/blob/master/onnx_skin_retouching/runtime.py)与[部署记录](https://github.com/aoguai/skin-retouching-onnxruntime/blob/master/docs/ONNX_DEPLOYMENT_REPORT.md) | 脸部平整、可选局部祛瑕与提亮候选 | 需权重及环境；检测不到脸可能原图返回，无脸型或身体几何能力 |

photo-cull-retouch 的本地 baseline 主要是白平衡、对比度、肤色阈值／平滑和锐化。彩妆、彩光或非人类肤色需核查阈值；这是从实现得出的适用性判断，不是效果实测。选片分数不代表角色还原度，弱滤镜也不自动成为“高级精修”。

仅在任务确需新引擎时再核当前版本、许可、模型与平台。历史核读中 GPUPixel 标 Apache-2.0，PixelFree 仓库有 MIT 文件但运行 SDK 另依赖授权，ONNX 代码和模型许可须分别核实；这些记录不代替当前许可检查，也不表示运行资源已取得。本包不复制第三方实现。

接入后在可回退样片上分别验证皮肤、五官、身体模块：是否真实改变对应像素，是否保住妆面、美瞳、假发与硬衣装，整体及原尺寸是否改善。检测失败、无效参数或回退弱滤镜如实记录；先执行并看结果，再记能力可用，不预先承诺与像素蛋糕等效。

## 按问题选路

| 问题 | 优先考虑 | 需要检查的边界 |
|---|---|---|
| 现有肤质、光色与轮廓 | 可执行的修复、曲线、颜色；小幅几何优先已验证的原生液化／位移，效果不足时按收益测试限定范围的生成候选 | 保持本人感与妆造，检查实际位移、保护区与完整连接，同时判断精致度是否充分；无几何工具不等于无需美型 |
| 身体定位不清、坐姿／遮挡 | 原图人工判断，按需运行身体参考 helper 辅助定位 | 高置信点也可错；人工复核后定轮廓与保护区，隐藏形体仍为推断 |
| 复杂补光与背景 | 生成参考候选或受控编辑，再决定直接采用、原图光色调整或局部融合 | 光线改善仍需单独核眼妆、美瞳、唇色、发饰和材质；不能把补光算作已完成五官／身形 |
| 假发／软布局部缺失或难修纹理 | 足够上下文的真实裁片约束生成，仅合入合格范围 | 供体可能移动结构，不能称原始细节恢复；对齐、材质和接缝均需看 |
| 衣带、鞋、球拍、专有武器 | 真实参考、连接与透视先行，有限试修后再细磨 | 可用材质不等于完整几何，自洽也不证明隐藏真结构 |
| 扩边或自主构图 | 按已确认取景有限试验，实际检查新增范围与动作是否达成 | 灰条仍在、花缘仍截断或人物并未重新布局都不算目标完成；新取景另确认 |

皮肤、假发、绒毛、蕾丝和丝袜按材质换方法。供体采纳范围外的脸、妆和饰件变化退回真实像素；原生方法足够时不固定先生成。

最新认可及保存状态见 [个人案例 NS08／NS09](personal-cases.md)；早期重绘、空场、大扩图、猜测枪尖均不追认为成功。只在需要复盘时读 [实验摘要](engine-experiment-history.md)，其中工具耗时不代表全流程速度。

## 速度、文件与恢复

复用建层、曲线、蒙版、已验证液化模块、位移编码与预览机制，按新图重定区域和强度。原蕾姆母稿约 1.61 GB、140 个含组层记录，减少重复合并、复制和全尺寸导出有实际价值；阶段用轻量全图与原尺寸局部，稳定后统一导出。网格与全画幅位移图仍遵守真实接口限制，导出发现问题仍需返修。身体参考只有定位收益明确时才运行，不把可选模型加载和整套合成探测加入每张固定流程。

历史备注：2026-10-07 的 previewBatch 候选像素／清理检查通过，但两组逐张／批量中位耗时 1222／1284 ms、1274／1409 ms 未证明加速，**未安装，也不是随包能力**。

连接超时后 PS 脚本可能继续执行，先查阶段标记、目标层和产物；共享 PS 写操作串行，独立只读诊断和固定候选复看可并行。回滚失败须保留日志、停止从不确定工作状态继续修改，不能宣称已撤回；先只读检查或返回已验证稳定源。生产细则见 [共用生产参考](production-retouch.md)。

历史生成服务未暴露具体型号，无相同输入、范围和验收标准的全流程速度对照，不称 GPT Image 2.5 或宣称提速倍数。PNGSaveOptions 曾在已转 sRGB 的文档导出时缺 ICC；需要补配置时只写入与像素相符的 ICC，并验证像素未变，指定配置不等于颜色转换。会话内对照按当前主 skill 和平台能力实现，旧尺寸不作默认值。
